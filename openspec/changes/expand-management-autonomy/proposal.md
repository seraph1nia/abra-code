# Proposal

## Why

The operator split management autonomy and remaining expansion out of `harden-operational-maturity` on 2026-10-18. The reliability checkpoint has unresolved native acceptance failures; additional autonomy must wait for those foundations and a fresh implementation request.

## What Changes

- Add explicit finite controller-owned project-lead grants and atomic delegated intake/accounting in the existing SQLite graph, preserving plan/merge/human approval ownership.
- Define revoke-first lifecycle behavior, immutable provenance and bounded management recovery across scope/session/restart windows.
- Add deterministic cross-task outcome coalescing with retained identities and no lost human decisions.
- Complete evidence-led locking/retention/simplification review and repeated acceptance/comparison assessment. Real providers and Firstmate execution remain separately authorized and optional.

This is planning only. No grant, task intake, scheduler extension, digest or migration is implemented by this change. The inherited design is provisional and must be re-audited after the reliability gate is green; prefer smaller changes at that point.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `project-leads`: Explicit scoped grants, bounded authority, revocation and lifecycle recovery.
- `batch-work-intake`: Atomic delegated task provenance and budget enforcement.
- `native-supervision`: Quiet outcome digests with preserved decisions and source identities.

## Impact

Future changes affect existing Leads, WorkIntake, graph claim transactions, Attention and native visibility. Reuse one controller, SQLite graph and native OpenCode service. No alternate harness, service, broker or UI framework. Grants cannot approve protected gates or widen global authority. See `original-scope/` for the superseded full proposal/design/tasks; those are historical planning, not implementation receipts.
