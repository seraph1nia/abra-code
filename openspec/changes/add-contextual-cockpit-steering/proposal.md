# Proposal

## Why

A developer can inspect a precise change in AbraCode and still have to describe it again in chat. The selected worktree content can change while the developer types, and later activity on the same issue does not establish which request a worker addressed.

## What Changes

Deliver four usable increments in this order:

1. Attach one exact diff selection to the main Abra draft, send it, and reopen the captured excerpt and its linked follow-up after reload or worktree retirement.
2. Promote the existing inspector into a resizable review canvas. Put accepted scope, changed code, observed behavior, independent findings and the next decision together. Retain a worker-selected screenshot as evidence.
3. Let a returning developer distinguish current decisions from material changes in recently inspected work. Expose queueing and current-turn steering on the same composer.
4. Extend the same interaction first to a plan criterion, then to a screenshot region. Surface an existing Playwright trace and worker-provided symbol or versioned documentation references in verification results.

## Capabilities

### New Capabilities

- `contextual-steering` binds a developer's question to an exact piece of work and correlates the response across the Abra conversation and its workers.

### Modified Capabilities

- `work-visibility` gains a resource-focused verification canvas and a device-local return-to-work view.
- `browser-cli` gains explicit retention of selected worker screenshots from assigned browser sessions.

## Impact

The change touches the web draft, composer, router, Pierre viewer, headless CopilotKit tool cards and workspace observation. Extend the browser-safe contracts, native admission and communication paths, scoped evidence reads, and worker reporting guidance. Keep the current SQLite work graph, OpenSpec planning artifacts, OpenCode session and controller checkpoints as their respective authorities.

## Scope and Choices

- A route describes what is open. A session draft owns its optional attachment. A sent request owns its immutable capture. AG-UI carries live summaries, while the canvas loads heavier evidence on demand through existing typed reads. The single composer stays mounted on desktop and mobile.
- Keep routine verification layouts in shared React presentation. Use the existing A2UI catalog for requested comparisons and generated reports. Chat cards, canvas sections and generated views navigate to the same owned resources.
- First admission validates mutable evidence on the server. Recovery looks up the original reservation first. Stale drafts can be updated or detached explicitly. Historical links open captured evidence even when the task has moved on.
- The fourth increment integrates evidence from tools the repository already uses. Installing Serena or Context7, adding a general tool marketplace, embedding a trace viewer, and cross-device read tracking are separate decisions. Existing review forms, offline reports, plain-text submissions and bookmarked work views retain their contracts.
