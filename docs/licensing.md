# Licensing and release evidence

AbraCode-owned code and documentation use the root [MIT license](../LICENSE).
Third-party code, generated instructions, data and external tools retain their own terms. See [third-party notices](../THIRD_PARTY_NOTICES.md), the pinned [inventory](../licenses/inventory.json), and retained full license texts in `licenses/texts/`.

The first release distributes source for a Linux clone installation. `node_modules`, downloaded executables, local configuration and runtime data are excluded. The operator's frozen pnpm installation downloads dependencies from their suppliers. OpenCode and OpenSpec declare MIT; agent-browser declares Apache-2.0. Their embedded components and browser downloads retain their supplier's terms. The root MIT grant does not grant provider accounts, model access, trademarks or rights to managed repositories.

The inventory records reachability from application runtime, contributor build, report authoring and report artifact entry points, separately from executable/optional supplier installation categories. The inventory distinguishes installed supplier components and optional platform packages not installed on the audited Linux target. It retains package version, registry provenance, integrity, supplied author attribution, license expression, actual license text hashes and review disposition. Where a supplier provides a declared SPDX license but no separate notice, the inventory records that limitation and preserves the standard terms and supplied attribution; it does not invent an upstream copyright notice. Khroma's actual MIT file supplies evidence missing from its metadata.

Lightning CSS (MPL-2.0) and ELK (EPL-2.0) are installed build/diagram tools. Their engines are not embedded in the offline report HTML: diagram authoring renders SVG before the report bundle is built. Keep their source/license rights and upstream links when redistributing those components. Creative Commons data packages retain their author/publisher attribution. Dual-license OR expressions use the documented permissive alternative. OpenSpec-derived skills and commands retain the upstream MIT notice in `licenses/openspec.txt`; AbraCode-specific adaptations do not erase that notice.

Run `pnpm licenses:check` before a release. It checks the frozen lock, reviewed dispositions, text hashes and copied-source hashes without network access. It also runs fixtures proving that unknown rights, unreviewed versions and missing/stale evidence fail. `pnpm licenses:refresh` is a maintainer operation that fetches registry/upstream evidence; new or changed component evidence becomes pending review. Review the diff and actual license files, update notices and dispositions, then rerun the check. Refresh alone does not approve a license.

If distributing native binaries, bundled JavaScript, generated reports or modified upstream code beyond this source-installation contract, review the actual new artifacts and their obligations before release. This inventory is bounded evidence for the recorded distribution, not a guarantee about arbitrary downstream bundles.

The reporter build embeds project and bundled report-runtime license/author notices in the standalone HTML's `abracode-license-notices` JSON block. This travels with moved/exported copies. Mermaid/ELK/Lightning CSS authoring engines are excluded from that runtime bundle; keep the source distribution's complete inventory and notices for authoring installations.
