# Effect v4 audit

AbraCode pins Effect 4.1.4. Shared contracts already distinguish issue, repository, execution, commit and tree identities. The runtime uses Effect for process lifetimes, scheduling and service assembly. The most valuable remaining changes are at boundaries where a filesystem failure, a malformed value or a caller's cancellation loses its meaning.

**First fixes.** Carry the web submission ID into the answer tool, decode Git object IDs in visibility reads, and distinguish a missing setup file from a failed filesystem probe. Each changes what a caller can successfully do or recover from. [Prioritized adoption order](#final-review-and-adoption-order)

## Native runtime implementation

The application scope now owns locks, coordination, records, work-graph access, operations, GitHub refresh fibers, detail caching and agent memory. Fresh execution creation requires the configured catalog. Recovery uses the retained configuration. Capacity admission audits records before taking the exclusive lock and rechecks the revision before committing. Forced detail reads fence older completions and expire on the calling fiber’s clock.

The findings below record the earlier audit. The current implementation and its verification checklist are tracked in the [native runtime change](../openspec/changes/modernize-native-runtime-and-drop-legacy/tasks.md).

### Use the submission ID wherever an answer refers to a web question

A web submission and the native `selection_answer` tool disagree about the same identifier. The web contract accepts `_selection`, which the answer tool's work-graph `RequestId` rejects. The work identifier accepts `a.b`, which web admission rejects. Both outcomes were confirmed against the installed schemas. A worker message's selection-source reference also uses the work-graph type. This can leave a valid admitted question impossible to reference through these interfaces. Keep the worker message's **own** request ID typed as `RequestId`. Give the **referenced submission** a `WebSubmissionId` over today's web grammar and carry it through admission, marker parsing, receipt lookup, selection-source inputs and the answer tool. Put it in a dependency-neutral contracts module. Preserve historical receipt and message reads, including their broader legacy shapes. Exercise admission → answer → reread with a leading underscore and test that two retries still use one storage key. Preserve the special missing-pointer case, digest comparisons and file ownership checks. ### Measure elapsed work with a monotonic clock

`measureReconcile` subtracts two wall-clock readings and clamps a negative result to zero. A clock change can still inflate a duration or record a spurious zero. The process output collector also uses epoch milliseconds to throttle progress, while its emitted `at` field genuinely needs wall time. Use `Effect.trackDuration(reconcileDuration, Duration.toMillis)` for the metric and monotonic readings for the throttle. Verification also throttles on `output.at`, so migrate both checks or define one owner for throttling. Keep wall time for the emitted observation. Preserve the metric's millisecond unit and its finalizer on every exit. The lock adapter already demonstrates the conversion. ### Separate durable deadlines from elapsed time

Delivery waits, cleanup blockers and PR feedback failures compute the same capped delay from a one-based attempt count. Delivery notifications compute it from the prior count. Extract the pure calculation and pass the attempt number explicitly at each call site. A one-based attempt sequence currently yields 30, 60, 120, 240 and then 300 seconds. Use named durations and convert to milliseconds when forming the retained epoch deadline. Keep the counter reset conditions with each owner. An in-memory retry schedule would lose the persisted due time on restart. `timestampAt` also already converts epoch milliseconds into the project's UTC brand. Reuse it in message completion, lead completion and read-model timestamps. Keep the strict accepted timestamp grammar and the local calendar-day semantics in fleet reporting. ## Fibers, queues and resource ownership

### Make the application scope own keyed background work

`Operations` constructs a private scope and runs `FiberMap.make` synchronously. `GithubInbox` constructs another scope, two maps of fibers and a semaphore. Both depend on the controller's explicit close path. The current application registers cleanup and has shutdown tests. A scoped constructor at application assembly would express the lifetime in `R`, attach cleanup immediately and give fixtures the same ownership as production. Preserve the operation-local scope, cross-process locks, generation checks and the requirement to stop workers before SQLite closes. Use `Cause.hasInterruptsOnly` when converting a pure cancellation to `STOP_REQUESTED` in `Operations.owned`. The present any-interrupt check also replaces a mixed cause containing a failure or finalizer defect. Exercise both exits. ### Consider a bounded queue for diagram compilation

`DiagramBatch` is the clearest remaining queue candidate. It implements two active slots, eight FIFO waiters, a deadline spanning queue and render time, shared per-source promises, caller detachment and renderer cleanup. The current nested `finally` already releases slots after cleanup failure. A plain backpressured `Queue.offer` or a semaphore by itself changes the public busy/timeout behavior. Preserve the Promise/AbortSignal API, per-batch renderer reuse and byte-bounded cache. ## Final review and adoption order

1. **Fix behavior at the boundary that knows what failed.** Start with the web question that cannot be answered, Git observation and onboarding defects, and setup's initialization gate. Each is independently testable with an accepted identifier, malformed runner output or a disposable filesystem. Handle renderer metadata the same way. These changes use the current wire formats and work without a service-layer migration.
2. **Keep validated facts intact.** Make approval evidence a discriminated union and carry finding identity through its reader. Reuse the decoded verification and review evidence in publication. Derive agent input types from their schemas as the corresponding interfaces change. The acceptance checks are legacy record reads, correct digest bytes and compiler rejection of a mismatched identity.
3. **Keep error and environment types where callers need them.** Move execution-policy rejection inside the declared Effect. Generalize the coordination callbacks, then move domain-error conversion out of transparent progress decorators. Acquire dependencies at application assembly or declare them in the operation's environment. A typed caller should be able to recover its own error and supply its own test service through a wrapper. Keep domain outcomes such as waiting and recovery in the successful value when the controller persists them.
4. **Match lifetime and time to the operation.** Preserve mixed failure causes on interruption, forward the diagram caller's signal, cache successful acquisitions, and use the monotonic clock for elapsed time. Use the Effect wall clock for persisted observations and due times. Investigate the intermittent lock-exclusion assertions recorded below before changing the lock or operation lifetime. Migrate private fiber scopes when changing their owners. A diagram queue rewrite has the highest compatibility cost and can wait for a concrete scheduling need.

The report monitor has one scoped worker and a one-slot dropping wakeup queue. An extra tick asks it to reread durable state. The workspace feed merges pending change scopes and uses a sliding PubSub for fan-out, with baseline/sequence repair for clients. A wakeup queue suits a single consumer, while independent observers each need a subscription. Keep native prompt admissions, approvals, operation generations and cross-process locks under their durable owners. React render lifecycles, SDK AbortSignals, UI debounce timers, pure projections and one-shot licensing/build scripts also have clear existing owners. [Monitor](../packages/runtime/src/recovery/monitor.ts) · [Workspace feed](../packages/runtime/src/web/agent.ts) · [Browser transport](../apps/web/src/workspace-state/observation-transport.ts) · [Architecture](architecture.md)

The browser already uses `AtomHttpApi` for typed server queries and cache invalidation. Its React consumers can keep their native lifecycle. [Workspace queries](../apps/web/src/data.ts) · [Review queries](../apps/web/src/review-data.ts)

The repository already enforces Effect diagnostics, defines agent services as layers, uses scoped acquisition for SQLite and child processes, and uses `TestClock` and `Deferred` to verify scheduling and interruption. Use those patterns for new runtime I/O, and use ordinary functions for deterministic policy and rendering. At public interfaces, declare the successful domain value, the failures a caller can act on and the services still required. Let TypeScript infer the intermediate generator types.
