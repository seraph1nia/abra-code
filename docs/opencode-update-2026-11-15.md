# Dependency update and OpenCode adoption report

Reviewed on 2026-11-15. The comparison starts at AbraCode's pinned OpenCode **2.0.28** and ends at the published **2.3.0** release of 2026-11-13. Recommendations below are engineering judgments based on the installed public declarations, upstream release notes, and AbraCode's current adapters. Optional features are recommendations, not enabled integrations.

The strongest follow-ups are **background-job visibility**, **keyed session instructions**, and a **read-only desktop work panel**. Keep SQLite, OpenSpec and the existing controller as the authorities for work, tasks and lifecycle gates.

OpenTUI 0.8.4 requires Node >=26.4.0; the application engine and build target now reflect that requirement. Node 26.13.0 is the selected mise version available under its release-age policy. The latest stable Node type package matches the new runtime major.

The Effect override gives host-facing dependencies one installed 4.1.4 implementation; OpenCode's client declares a 4.1.0 peer. This patch-level departure is explicit in the peer policy and requires the real native acceptance tests. Vite+ also uses its own version in the Vite alias, so its peer exceptions remain explicit. The Effect tooling versions match the upstream [supported-version table](https://github.com/Effect-TS/tsgo#supported-package-versions).

The follow-on OpenSpec 2 instruction migration is complete: all six generated workflows now use the shared `.agents/skills` tree at version 2.0.0, and the twelve legacy tool-specific files are removed. Real CLI regression coverage verifies repeated refreshes preserve AbraCode's project-owned skill bodies and role profiles. See [instruction ownership](openspec.md).

Compatibility work includes the plugin's exact runtime guard and service-discovery version, renderer-owned syntax styles, the rendered prompt-footer slot, generic event-subscription filters in the fault fixture, and the OpenSpec 2 generated-skill location. Native launch assertions strip terminal control codes before checking visible text. The native report fixture resolves its explicitly provisioned browser before isolating its cache, so report builds use that same browser without installation or global discovery. New Effect diagnostics use `Effect.isSuccess` for existing boolean checks; narrow platform-adapter comments document the required unstable APIs. The generated configuration schema now includes Effect's safe-integer maximums and normalized constraints.

pnpm 12 stores toolchain and application resolutions in separate YAML documents. Licensing now reads both, rejects conflicting entries, and includes the package manager in build reachability. New regression coverage proves that an unreviewed toolchain dependency cannot disappear from the audit. Supplier license evidence and notices were refreshed. OpenTUI's platform binaries now declare **MIT AND LGPL-2.1-or-later**, including FFmpeg; the source distribution excludes those binaries. Retained notices do not authorize a new binary distribution.

## Recommended implementation order

1. **Background-job observation and completion audit — highest priority.** Extend the native adapter with a bounded read-only job projection. Display kind, owner, status and observation time in worker details. First prove whether any currently permitted Apply shell can outlive a successful turn. If so, require owned jobs to be terminal or explicitly handed off before Review/retirement; unknown/unreadable job state must retain ownership. Test parent/descendant jobs, pause, restart and lost observations. Native idle and model text remain insufficient completion evidence.
2. **Keyed guidance — high value, moderate risk.** Keep immutable assignment capture in `workflow/worker-context.ts`. Derive one namespaced key per assignment/control generation and put the corresponding guidance during a deliberate admission. Reconcile exact existing entries before retries; supersede stale keys when authority changes. Remove only entries owned by AbraCode. Test captured legacy sessions, role/model changes, compaction/revert, response loss, and absence of extra turns. Measure cache improvement before removing the existing system-text path.
3. **Filtered events and retry diagnostics — bounded follow-ups.** Pass an explicit event-type list to `monitor`; adapt injected fixtures and preserve reconnect/timer behavior. Separately add optional bounded retry timing to error projection and visibility, with compatibility decoding for old records. Test delayed observation and admission uncertainty rather than adding automatic prompt replay.
4. **Desktop observer — product improvement.** Add a GUI-only entry using native components and the existing visibility protocol. Start with work list, detail, retained report and read-only worker selection. Test both local and remote authenticated endpoints, plugin activation, offline freshness, host disposal, and proof that selecting a worker never calls `session.prompt`. Keep decisions in Abra and native bound forms.
5. **Artifact publication and performance experiments — opt-in prototypes.** Preserve self-contained offline HTML as the durable deliverable. Add native artifact access only after verifying storage ownership, sanitization, provider lifecycle and authenticated/remote URLs. Benchmark cache TTL/background compaction on the existing operational harness. Do not enable goals, schedules, shell backgrounding or new generation tools merely as part of a version upgrade.

Each implementation needs its own scoped controller-managed work item; this report does not authorize or launch its recommendations. No optional feature flags, provider credentials or production service settings were changed for this dependency update.

## Verification and limits

Final acceptance passed `pnpm check`, all **487 unit/integration tests**, all **3 end-to-end tests**, build, configuration schema, formatting, license checks and diff checks. The direct-package registry audit returns no outdated dependencies and the peer audit has no issues. Exact outcomes and retained native evidence are recorded in the accompanying update entry in [API evidence](supported-apis.md). The native and installation suites use disposable homes, deterministic loopback models and local bare remotes. They do not establish live-provider quality or production forge permissions.

The follow-on OpenSpec instruction migration passed the expanded **492-test**
unit/integration suite and all **3 end-to-end tests**, plus the strengthened
7-test refresh regression and final static/license checks. Its retained native
evidence is `/tmp/abra-openspec2-final-verified`; the [migration acceptance](release-acceptance.md#openspec-2-instruction-migration-acceptance--2026-11-15)
records the scope, fixture correction and concurrent checkout work.

The v2.3.0 graphical [file renderer](https://github.com/anomalyco/opencode/blob/v2.3.0/packages/gui-plugins/src/file/renderer.tsx) and [artifact viewer](https://github.com/anomalyco/opencode/blob/v2.3.0/packages/gui-plugins/src/file/artifact-view.tsx) were inspected. HTML still uses an opaque iframe with the existing sandbox flags and a no-referrer policy. Portable report and sandbox interactions have browser-test evidence; actual paired desktop click-through, a GUI plugin, and experimental artifact publishing require separate acceptance.
