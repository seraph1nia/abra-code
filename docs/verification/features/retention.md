# Preservation, retirement and restart

## Sub-features

Preserved branch/merge evidence, conservative temporary-resource disposal, restart without repeat delivery, and retained worker-admission compatibility.

## How to get to it (user POV)

The controller owns delivery and retirement after verification and Review. An ignored fixture residue arriving after guarded merge submission deliberately blocks removal. Residue present before submission instead requires disposition before merge approval/dispatch. Inspect status/detail after restarting the fixture service; answer the recreated exact-action native form for fixture-owned generated residue. Reconciliation continues automatically; preserve a new unknown sibling elsewhere only after its separate preservation decision.

## Driving it with the existing harnesses

After the [recipe prerequisites](../README.md#prepare-and-check-health), run:

```sh
pnpm exec vp test run --project e2e tests/e2e/native.test.ts
pnpm exec vp test run --project unit tests/unit/retirement.test.ts tests/unit/worker-lifecycle.test.ts tests/unit/engineering-recovery.test.ts
```

Native expected state: delivery is verified while cleanup remains blocked across a service restart; authorizing only the known generated directory disposes of it automatically, while a new unknown sibling remains protected until explicit preservation and fresh absence permit retirement/closure, and the recording forge counts exactly one merge. Archived report/diff and captured context identity remain inspectable afterward. The native suite uses only local bare remotes.

Unit expected state: unknown/replacement paths survive cleanup, lost removal responses reconcile without another removal, and uncertain admissions preserve prompt/session/payload identities across controller reconstruction. Native-runtime preflight tests serialize a pre-suite capture, expose only old skill inventory, and require its exact requirements/provenance. Lost admitted responses skip inventory. Incompatible permission policy still blocks unsubmitted recovery; a deliberate fresh turn selects current defaults.

The engineering recipe also serializes a seeded historical capture before its native-server restart and checks exact retained prerequisites against the restarted server inventory; it does not submit the historical prompt. Fresh preflight selects current defaults.

The tests own their temp roots and cleanup; preserve runner logs using the recipe's external evidence directory. Unit fixtures do not start a service and need no browser.

## Gotchas

The full default native run includes reliable-finishing scenarios; `ABRACODE_TEST_JOURNEY=engineering` excludes those extra PR/finishing assertions. Inspect the actual retained result for the selected run. Scripted native acceptance and unit reconstruction are identified separately; neither establishes production restart behavior under every failure.
