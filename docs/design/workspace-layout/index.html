Finding your way through Abra

Keep the conversation one click away. Give work, GitHub and personal thoughts room to browse, and let one search open the exact item you came for.

What the sidebar is asking you to do

Try finding a closed local task. “Work” opens a column with a Thoughts button, a shared query, a project selector and a GitHub inbox. “Closed” inside GitHub filters selects remote issues and PRs. The “Closed” button farther down selects SQLite tasks. Capacity then sits between that filter and its results. Both lists have their own pagination, and the fleet total below them still covers every project. Each control makes sense in isolation. Their order makes it hard to tell what a click or a count refers to.

On a phone the same stack occupies the entire Canvas. On a first visit, Canvas means “find work.” On a later visit it may open yesterday’s report. Getting from chat to a note can include Canvas → Find other work → Thoughts → result → Ask Abra. A person who remembers the note’s wording still has to know where it lives.

Recommendation. Reserve the desktop sidebar for destinations. Put one collection and its own filters in the main area. Keep a single Abra conversation and make every durable item addressable through Search. On phones, expose Chat, Work and Thoughts directly.

Pane and history rules

Wide desktop: rail, primary content, and at most one contextual reader. A work-list click replaces the list with a readable detail and a Back to Work affordance. A chat evidence click keeps chat in view beside that detail. Tablet: keep the destination names accessible in a menu and show the reader as a sheet. Phone: use one primary surface and a Back destination. Keep the top search and attention controls reachable from any collection. Hide bottom navigation while typing if the keyboard leaves too little room.

Keep destination, collection filters, selected resource and source revision in navigation state suitable for Back and reload. Keep the unsent conversation draft, attached references, list scroll and reading position per Abra session. Preserve existing issue/tab/file/scope and exact-resource bookmarks. An item opened directly from a bookmark gets its owning collection as a return path. Dismissing Search restores focus to its trigger. Selecting a result moves focus to its heading, or to the composer for a draft action.

Two alternatives considered

Accordion sections inside Work would be a low-cost transition. It reduces the initial height, but the shared query, nested scroll and two different meanings of state survive. A project-first sidebar helps a single-repository workflow, but personal thoughts and cross-repository triage have no natural parent. Use repository as a remembered filter on Work and GitHub. Revisit a pinned repository shortcut if repeated journeys justify the space.

One search for items and commands

Search starts in All. Provide type filters, a Commands tab and keyboard equivalents such as thought:, session: and > for commands. On an empty query show recent destinations and frequent actions. A row shows type, human title, owning repository/task or notebook, and the effect of Enter. Return the exact ID first, then exact names, then contextual and textual matches. Reserve space for each matching type so a large task queue cannot bury a single matching thought.

What pressing Enter does

Open navigates to an item. Attach to chat adds a versioned reference or selected excerpt and preserves the existing words. Prepare draft inserts editable text at the caret, adds a newline when needed and focuses the composer. Selecting a template with a nonempty draft must preserve that draft. Open form takes the user to the existing decision or export control. Its own submit or download gesture performs the action.

Make the palette the discoverable catalogue. Add slash aliases only for frequent composer actions. Typing /onboard-repo at the beginning of a composer command opens the same “Onboard repository” entry as “add project” in Search. Choosing it prepares “Help me onboard a repository.” A user can add a path or URL, review it, then Send. /save-thought opens a draft for exact notebook wording. /attach-thought opens the thought picker and attaches the selected reference. Ordinary pasted code, code fences and paths beginning with a slash remain literal unless the user selects a command. Code snippets can be inserted as editable fenced text with source attribution; a selection tied to a file revision should use the existing attachment mechanism.

A shortcut for “pause this work” prepares the current issue-specific request. A result for “approve plan” opens the native bound form. Keep Stop current Abra turn visible only in its busy conversation. Ranking, aliases and navigation can evolve independently of the controller and its checkpoint checks.

Let a thought keep its source

AbraCode already reads the private personal notebook across projects. A selected thought carries instance, account, memo resource name and wording hash. The detail read verifies this identity and returns its original Memos URL. The save operation verifies the newly written memo and returns a reference; the accepted issue stores only the chosen excerpt and reference. The pinned Memos browser route was exercised with a signed-in, disposable account. Repository API evidence · Pinned Memos API

  1. After saving, resolve the verified reference and render a receipt with its first line, “Saved to Memos”, Open in Memos and Attach to chat. Retry an uncertain save using the same request identity.
  2. When using a thought, show a compact native card in the reader, draft and sent message. Include snippet, optional tags, date and original link. Expand on demand to read full text through existing detail. Use the same card on phone. Keep the private body out of generic search caches and global recent-query previews.
  3. When work is accepted, keep the exact accepted excerpt, account and memo identity. Show “Open original in Memos” and an optional live preview. If wording changed, keep the accepted quote and offer to select the current version for a new discussion. If the memo was deleted, access changed, or the configured account differs, preserve retained evidence and explain why live preview is unavailable.
  4. When following the link, use the configured notebook origin and validated memo resource. Opening on a phone needs a reachable origin and a signed-in Memos account; loopback there identifies the phone. Keep credentials server-side. Defer a full-page iframe until frame policy, authenticated cookies, phone ergonomics and a benefit over the native card are demonstrated.

A later “Used in work” section could read a reverse lookup of accepted thought references in the work graph. That gives the reader a path back to the resulting tasks. Writing reciprocal links into private memo text changes its wording hash; make any future Memos writeback a separate, explicit action.

Order of change and acceptance journeys

  1. Move the collections first. Use existing reads. Move the GitHub filters and rows together; give Thoughts a route; keep the old finder bookmark meaningful. Exercise local Closed versus remote Merged and return to the same list page.
  2. Expand search and draft actions. Ship Work, Thoughts, GitHub, Settings and commands, then the bounded session lookup. In a workspace larger than one page, find a closed task and a worker by ID. With one provider unavailable, select a result from another. Start onboarding from Settings, Search and slash with a half-written draft.
  3. Carry references through chat. Save a thought, attach it, send a question, accept an excerpt and follow its original link. Change the memo and repeat with the old reference. Verify that the captured excerpt stays readable.
  4. Complete evidence discovery. Add task-scoped metadata for reports, findings, reviews and communications, then cross-task indexing where needed. Test exact revisions, missing sources and Back on phone. Use a real phone keyboard and screen reader before committing the new navigation.

Basis and limits

This study follows the current checkout of the operator web workspace, shared presentation components and portable report viewer. Desktop header/finder and phone Chat/Canvas navigation were checked in the running app. Conditional native forms, uncommon evidence states and offline views were inventoried from their renderers and verification recipes. The mockups use invented records. They illustrate information placement and selected journeys, with no connection to the notebook or controller. Chart families include work already in progress in this checkout.

Trace the implementations in the workspace, finder, GitHub inbox, palette, inspector, evidence renderers, shared views, portable viewer and thought adapter. The Memos journey describes the native checks.
