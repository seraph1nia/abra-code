    The browser reserves feedback in the controller, then answers the native form in a separate call. I interrupted that sequence after reserving “Request changes.” A retry with one punctuation change failed. I simulated an approval through the other native surface and reconciled.     P2A busy worker can freeze its own Live session

    I opened a worker’s transcript, gave subsequent history reads 850 ms latency, and sent 60 session notifications 100 ms apart. During the burst, 18 new reads started and zero finished. After the burst, the updated text appeared. The fixture counted 18 interrupted reads in total. Slow service is where a person most needs the window to keep moving.

    P2A supported checklist can invalidate its own approval

    I copied the compact schema to a temporary repository and configured its task artifact and tracking path as implementation.md. OpenSpec 2.0 correctly reported 0/1 and then 1/1 when the checkbox changed. AbraCode computed a different plan fingerprint. The same edit in tasks.md kept its fingerprint. A custom-schema task can therefore complete a legitimate step and fail its next plan check.

    Have the OpenSpec adapter identify tracked task markers from the bound schema. Normalize only those markers for approval identity. Version that calculation for new executions and preserve existing fingerprint semantics for active receipts. Exercise approval, completion and archive with an alternate tracking path.

    P2Attention can show the approval without the evidence

    The inbox renders a task ID, fingerprint and buttons. Its deduplication removes the matching task row, and the form itself has no link to the plan or merge report. The task page has more context, so the amount of information available when approving depends on how someone arrived.     P2The outcome report loses the accepted full-spec criteria

    The overview takes criteria from the short scope and falls back to the original description for the goal. An ordinary full-spec plan keeps its accepted choices and acceptance text in planning artifacts. Those can evolve after intake. The verification wire exposes pass, findings, session and fingerprint, while the independent reviewer can also record completeness, correctness, coherence and conflicts. The report cannot join much of that evidence back to what the person approved.

    At plan acceptance, capture a small display projection of the accepted revision with source references. At review, reuse check receipts and review assessments, linking each criterion to evidence when that evidence exists. Leave unassessed criteria visible. Bind completion evidence to the delivered revision so a retired task can reopen the same report.

    When to involve the human

    Intake
    Abra captures outcome, scope and observable success. Resolve material ambiguity in one short question. A bounded fix uses the existing short contract. Research gets a question and a report. A change to durable behavior gets a tracked plan.
    Before Apply
    When policy requires approval, show intended behavior, boundaries and consequential choices alongside Approve plan and Request changes. On revision, show the difference from the last proposal. A missing or undelivered form means Abra owes the next action.
    During work
    Show observed checklist progress, the current worker and the last meaningful update. Expose diffs and read-only sessions on demand. Bring the person back for a blocking decision or scope change. A worker owing another agent an answer belongs in task activity.
    Before merge
    Show the head being approved, changes since the prior reviewed head, check freshness, independent findings and unresolved risk. Keep the actual decision beside that report. A request for changes should reopen the task with the person’s words and an attributable revision.
    After delivery
    Distinguish merged, branch preserved and research delivered. Show the accepted outcome and the supporting revision or report. Surface remaining cleanup only when it requires action. Keep the report readable after worktree retirement.

    Two artifacts are enough for the person

    Plan answers “What did we agree to, and how far has it got?” Report answers “What actually happened, how do we know, and what remains?” Diff and Live session are evidence views. Keep the summary above the four views so it travels with the task.

    The current change itself has 2,798 whitespace-delimited words across its proposal, checklist and four delta specs. It was authored against compact v1. This repository now defaults to compact v2, with no mandatory design artifact. Other managed repositories select their own default. The v2 proposal already asks for outcome, scope and acceptance. Shorter templates can improve authoring, but cannot repair a missing handoff from the accepted plan to the report.

    Retain OpenSpec’s revisioned source, tracking, validation and archive for work that needs these capabilities. Keep deeper scenarios behind “Planning sources.” Let simple fixes and investigations use AbraCode’s existing short scope. Reconsider replacing the planner if two routes, given equally concise inputs, show a material difference in authoring turns, time to approved intent or correction frequency. Measure on comparable tasks first.

    Firstmate’s applicable ideas are one liaison, a visible crew, and escalation of decisions with plain outcomes. Its Calm presentation hides operational inputs while retaining the session history. AbraCode can adopt that presentation rule in the web client while keeping its controller and exact approval receipts.

    Implementation order

    1. Make decisions recoverable. Preserve existing native-only receipts. Use a single resumable response operation for web and native reconciliation. Ship the interrupted-reply regression before changing the inbox.
    2. Fix what progress means. Give the live transcript a bounded refresh queue and the plan a schema-aware identity. Test a sustained stream and a real custom-schema checkbox through the checkpoint.
    3. Build one task reader. Resolve legacy Overview, Activity and Verification links at the routing boundary. The task page, chat split and phone sheet should host the same four sections and exact evidence targets. Currently the inspector translates tab names, reinterprets clicks on a selected tab and chooses a different component depending on entry point. This adds more complexity than the sidebar’s styling.
    4. Use the same facts everywhere. Extend the current visibility model with accepted criteria, the next owner, action and evidence target. Have Plan and its header share an observation. The header requests overview while detail independently builds that overview again. Keep each store authoritative for its existing data.
    5. Quiet the default surfaces. Give Work and Attention the main reading area. Keep the rail for destinations and one actionable count. Put the summary once at the top. On Report, show available results first and disclose attachments, source documents, history and identifiers. In the browser fixture, opening Report produced six evidence headings even with no check or Review receipt.
    6. Shorten agent handoffs at their source. Keep distinct message states for admitted, acknowledged and answered. Only surface the state that changes a human decision. A clarified short scope can enter the next worker prompt twice, as a serialized decision answer and as the accepted contract. Supply the contract once and reference its provenance. Represent requested revisions as typed receipt references. Currently the controller builds an error message telling Abra to manufacture a checkpoint- finding ID and the correction path interprets that string again.
